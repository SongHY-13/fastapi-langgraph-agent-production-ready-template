# 04：研发交接与实施顺序

更新：2026-11-02；范围以 [总体设计](03-ai-consultation-design.md) 和 [需求覆盖/材料表](07-materials-and-acceptance.md) 为准。同事已跑通模板，现有工作流仍是设计稿，业务可以按真实需求重新组织。

## 1. 阶段与交付

| 阶段 | 可交付结果 | 验收重点与依赖 |
| --- | --- | --- |
| A：接口和数据基础 | 平台可信主体、业务会话/消息/任务、固定数据的合同样例、SSE/取消、页面能力编码 | 小程序真实终端分帧/重连、跨用户隔离、幂等、取消竞态；认证/场景字典需同事确认 |
| B：知识与普通问答 | RAGFlow adapter、文档发布目录、三类检索、真实引用、澄清与无命中兜底 | 先用明确标记的演示资料；生产需客户审核知识、政策/流程及其有效状态 |
| C：人工和安全闭环 | 前置风险、输出审核、主动人工/两次无答案入口、outbox/worker、普通超时提醒、紧急转介 | 真实工单/值守接口、资源及风险策略、人工受理/回复与补偿；这是对外试运行前必需项 |
| D：会话与运营 | 历史分页、一般删除/高风险锁定、加密/展示脱敏、FAQ、联想、反馈与知识更新 | 客户留存/密钥与后台权限、指标定义、内容审核与撤回、业务转化回传 |
| E：端到端验证 | 语音边界集成、性能/可靠性、业务验收数据与运行手册 | 真实环境、模型与凭据、ASR/TTS归属、并发与服务时限、受控试运行 |

以上为工程推进顺序，不表示可以在缺少安全/人工能力时对外上线。阶段 A/B 可在内网用模型与接口替身演示；真实咨询开放前完成相关阶段的风险与授权验收。语音若由平台提供，可提前并行对接，不阻塞文本链路。

## 2. 首轮实现建议

先评审 [05 接口合同](05-api-contract.md)：身份签名、会话归属、消息与任务 ID、事件、取消、功能编码、来源与人工状态。随后建立真实异步业务数据库访问和迁移，再将工作流节点逐步接入；不在原自由工具循环上堆叠所有需求。

首个可验证闭环为：可信用户 → 创建会话 → 提问 → 受控检索/澄清 → 审核后答案与来源 → 停止/状态查询 → 历史。同步提供人工/风险接口替身以验证路由，但界面必须标为演示或待接入，不能显示虚构的派单成功。

## 3. 必须优先确定的输入

- 平台同事：鉴权与用户上下文、SSE/分块能力、功能编码、工单与通知接口、人工状态和消息渠道。
- 客户：三类审核内容、政策适用性元数据、风险策略与值守机制、紧急资源、未成年人通知、留存和删除规则。
- 运维/团队：模型和 embedding/reranker、RAGFlow版本及资源、访问地址/凭据、加密密钥管理、目标并发与延迟。

完整字段、样例要求和接收标准见 [07](07-materials-and-acceptance.md)。内容不足时允许构建 schema、mock、合同测试和索引发布机制，但不能从互联网自行填充后标为客户权威知识。

## 4. 测试分层

| 类型 | 应验证的行为 |
| --- | --- |
| 确定性测试 | 授权、风险优先、限次澄清/改写、无法回答计数、引用和动作白名单、幂等、取消、锁定删除、回调乱序 |
| 集成测试 | PostgreSQL/checkpoint、RAGFlow真实版本、过期知识过滤/撤回、worker重启、工单和通知失败/重试 |
| 小程序端到端 | 分帧/重连/停止、来源查看、功能跳转、人工回复通知、语音低置信度降级 |
| 质量评估 | 领域正确与可溯源、政策地域/时间适用、风险误报/漏报、无命中与违规拒答；阈值由专业/产品确认 |
| 运行验证 | 首字/完成延迟、峰值并发、模型/检索故障、密钥与敏感数据边界、删除任务、指标与报警 |

`evals/` 的 LLM 评分不能代替授权、可靠派单或引用真实性测试。新 Python 代码遵循 AGENTS.md，执行 Ruff、格式和 Pyright；不为纯文档改动添加与业务无关的测试。

## 5. 对接纪要模板

每项待确认内容记录：负责人、提供日期、版本/来源、样例、验收标准、变更通知与当前状态。明确人工单主系统、会话/录音/风险证据的持有方，以及平台和AI两边故障时各自负责的补偿动作。
