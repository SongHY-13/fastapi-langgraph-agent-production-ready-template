# 07：客户资料、协作接口与验收清单

更新日期：2026-11-02。依据本次确认的 AI 咨询需求整理；本系统提供供小程序及其平台服务调用的后端能力。用户账户、悬浮窗和业务页面由现有平台承接，匿名账号和匿名咨询入口不属于本次建设范围。

本文中的接口字段、状态和验收场景是待双方确认的合同草案，不代表代码已经实现或客户资料已经交付。已有工作流的补充设计见 [工作流](../workflow.md)，取消与事件字段以 [接口合同](05-api-contract.md) 为准，RAGFlow 接入约束见 [检索接入说明](06-ragflow-integration.md)。

## 1. 责任边界

| 参与方 | 主要交付 | 需要共同确认 |
| --- | --- | --- |
| AI 咨询后端 | 咨询会话、检索与有依据作答、风险识别、安全过滤、流式事件、引用、推荐动作、转人工/转介对接、反馈和问答质量数据 | 服务鉴权、风险和转接规则、保留期限、语音归属、统计口径 |
| 小程序前端 | 全局悬浮球、拖拽与位置记忆、半屏/全屏/收起、消息和来源展示、停止按钮、功能卡片、麦克风授权、语音交互、用户反馈控件 | 流式协议、失败状态、来源打开方式、前后台切换后的续接行为 |
| 平台后端同事 | 现有登录态校验和可信用户身份传递、业务页面动作字典、工单/客服/消息通知适配、转化事件关联 | 是否代理流式请求、工单系统归属、状态回调、用户与会话权限映射 |
| 客户业务及专业负责人 | 经审核的知识、政策、流程、FAQ、风险处置规范、服务资源清单、人员值班和处理机制 | 内容发布、失效下架、人工处置时限、未成年人通知与数据访问权限 |
| 运维或双方指定负责人 | 模型与 ASR/TTS 凭据、环境资源、密钥管理、数据库备份和任务运行、监控告警 | 部署责任、故障联系人、可用性及容量目标 |

语音识别、语音合成、客服工单和运营界面若已由平台提供，AI 服务对接既有接口；没有现成能力时需单独确定承建方，不能默认为模板已经提供。RAGFlow 管理页面用于知识处理与维护，不替代平台的客服、运营反馈和用户授权系统。

## 2. 逐项需求覆盖和验收依据

下表列出需要交付的行为，属于目标设计。除通用模板能力外，具体业务实现状态以代码和联调记录为准。

| 编号 | 需求 | AI 后端责任 | 其他方责任与材料 | 主要验收场景 |
| --- | --- | --- | --- | --- |
| R01 | 悬浮窗全局入口 | 提供稳定会话入口、可恢复的会话标识 | 前端实现拖拽、记忆、半屏/全屏、最小化及各页常驻 | 切换页面不新建重复会话；重开窗口能恢复明确的历史状态 |
| R02 | 现有平台用户接入 | 校验服务调用身份、映射可信用户、逐次校验会话归属 | 平台提供登录/网关合同和稳定主体标识 | 篡改请求中的 user_id/session_id 不能读写他人会话；小程序包内没有服务端长期密钥 |
| R03 | 多轮对话 | 保存轮次、上下文、已澄清槽位、消息状态和请求幂等键 | 前端发送本轮新增输入，按约定恢复历史 | 同一请求重发不重复追加；并发输入、追问和断线后的状态一致 |
| R04 | 流式输出与停止 | 定义事件 ID、顺序及独立的生成/传输状态，输出经过审核的内容，支持幂等取消 | 前端解析分块流、显示中止状态；平台代理不缓冲或截断事件 | 业务完成前取消才记 generation.cancelled 且不计无法作答次数；审核结果已落库的 generation 保持 completed，停止发送只记 delivery_status=aborted，完整已审核答案仍可查询、计数不回滚；内部判定和未审核候选不进入用户流 |
| R05 | 输入/输出敏感与合规过滤 | 区分知识教育与违规意图，入站和出站检查，固定拒答与安全兜底 | 客户给出分类、边界样例和审校口径 | 正常戒毒教育不因包含“毒品”等字样被一律拒答；违法交易等请求不输出可执行帮助 |
| R06 | 语音提问及播报 | 对接确认归属的 ASR/TTS 或接收平台转写文本；转写内容走统一咨询流程 | 前端授权麦克风、录音/播放；供应方提供格式、限额、置信度含义和错误码 | 识别失败/低置信度提示文字修订，不发送错误识别内容；停止播报与停止生成分别处理 |
| R07 | 戒毒知识问答 | 使用审核知识检索，回答与证据绑定，显示适用范围及已确认提示文案 | 客户提供科普材料、原始出处、版本、专业审校人和风险边界 | 有依据回答且引用可打开；知识未覆盖时不补造内容；医学高风险进入紧急路径 |
| R08 | 国家和江西政策问答 | 校验地域、时间、生效状态，返回名称/文号/原文出处；证据不足转澄清或人工 | 客户提供现行及失效政策、官方解读、适用地区、有效期和维护人 | 已失效政策不作为现行结论；日期/地区不明确先澄清；个案超出范围显示人工入口 |
| R09 | 办理流程问答 | 根据条件和上下文给出步骤、材料、时限及经校验动作编码 | 客户/业务模块提供办理口径、条件、材料、时限、流程版本、对应功能 | 同一业务变更后不引用旧流程；缺少关键条件先澄清，不猜测办理资格或时限 |
| R10 | 场景跳转和功能卡片 | 返回白名单 action_code 与允许参数，记录推荐来源 | 平台提供动作字典、权限条件、参数规则和转化回传；前端解析为页面 | 模型不能生成任意路由/URL；卡片按用户权限展示；目标模块收到 source=ai_consultation 等约定来源标识 |
| R11 | 转人工 | 识别用户显式请求和业务无答案状态；生成摘要、转接请求和可追踪状态 | 平台/客户提供工单、受理排班、回复、通知和状态接口 | 用户主动要求时进入人工路径；同会话连续两轮 unable 时展示入口；重复点击只建一个有效请求 |
| R12 | 高风险识别 | 在常规检索/生成前判断风险，并允许后续信息触发升级；记录触发依据和处置状态 | 客户提供风险分类、确认样例、专业审校和升级规范 | 关键词、语义和上下文共同覆盖；风险判断故障不直接放行常规生成；新消息复查，不沿用旧的低风险标签 |
| R13 | 紧急处置与转介 | 抢占常规流程，持久化风险事件和待派发任务，立即返回核验后的紧急资源/人工通道 | 客户核验资源服务范围及可用性，指定接收人员、通知与处置责任 | 外部工单超时不阻塞紧急提示；不把派发失败显示为已受理；用户取消常规生成不撤销已触发的处置事件 |
| R14 | 人工超时提醒 | 依据工单状态和时限产生持久化、幂等的后台提醒 | 客户/平台确认 24 小时口径、排班、催办对象及通知渠道 | 不靠保持请求连接或进程内 sleep；服务重启后待提醒任务仍在；已受理不再提醒，高风险不等待普通 24 小时规则 |
| R15 | 历史、摘要与删除 | 按用户隔离历史；普通会话删除与高风险受控保留分开处理；数据加密与脱敏展示 | 客户确认保留策略、角色权限、风险锁定/解除流程、备份与审计要求 | 普通会话删除后不再可读，后台写入不使其复活；受控留存会话返回明确的禁止删除状态，不能伪装成删除成功 |
| R16 | FAQ 热门、分类与联想 | 提供已发布 FAQ 查询、分类、排序、联想和计数接口 | 客户提供问题库；运营方负责上下线和展示顺序；前端提供入口和点击事件 | 未发布条目不返回；同一事件重试不重复计数；输入联想不能返回其他用户的历史文本 |
| R17 | 点赞/点踩/纠错/未解决 | 反馈绑定回答和可信用户，保留处理状态，按权限汇总 | 客户指定处理人、纠错流程；前端提供控件，运营界面承建方确认 | 不能评价他人回答；重试不重复反馈；纠错不会绕过审校直接写入已发布知识库 |
| R18 | 运营指标和质量改进 | 提供明确分母、状态分布、趋势、未命中和低分清单，关联知识版本 | 客户确认周期、目标值和运营流程；平台提供转化到达/办理结果 | 测试流量、业务完成前取消和系统故障按约定处理；完成后的传输中止不改写业务统计；指标可追溯到消息/事件，不只依赖模型自行判定 |

## 3. 客户需要提供的材料

### 3.1 首轮资料包：可开始构建与评估

| 材料包 | 至少包含 | 用途与校验点 |
| --- | --- | --- |
| 戒毒知识资料 | 正文或可获取的原文件、标题、专业来源、原文链接、出版/更新日期、审校人、适用人群和主题分类 | 构建知识库；核对正文可用、来源权威、版本和审校责任；不能只给网站首页或问题标题 |
| 国家/江西政策库 | 政策名称、文号、发布机关、正文/官方解读、官方来源、发布日期、生效日期、失效/废止日期、生效状态、适用地区、替代关系、审校人 | 防止无效政策继续作答；历史问法是否允许检索历史版本需确认 |
| 办理流程库 | 业务编码、名称、服务对象、前置条件、所需材料、办理步骤、时限、费用说明（如适用）、办理渠道、例外和人工咨询方式、版本与维护人 | 输出可执行且与平台一致的步骤；AI 不自行补齐缺失时限和条件 |
| 常见问题及标准答案 | 问题 ID、主题分类、问题及别名、审校答案、证据链接、展示顺序、发布状态 | 首屏推荐、联想及首批验收；热点排序与运营置顶的优先级需确认 |
| 参考问题和反例 | 典型追问、含糊表达、知识未覆盖、政策个案、违规请求、紧急风险、人工请求及预期处置 | 形成可复现的测试集；必须包括“不应回答/需澄清/应升级”的样例 |
| 内容发布规则 | 起草、专业审校、发布、定期复核、失效下架的责任人和更新频率 | 定义知识版本、更新时间和撤回机制，避免生产查询读取未审校内容 |

启动阶段可先提供每类少量有完整出处的代表材料，用于检索和引用验证；覆盖面和质量验收需要完整资料及双方确认的测试集。具体数量、比例和通过阈值需在验收前约定，不能以演示样本通过代表领域覆盖完成。

### 3.2 风险、人工和数据治理资料包：上线前必须确认

| 材料 | 需要客户给出的决定 |
| --- | --- |
| 风险分级与处置矩阵 | 自伤自杀、急性中毒、严重戒断、复吸危机等类型；不同级别允许的系统动作、人工优先级、触发条件、负责人及审校文案。关键词只是检测信号，需补充语义/上下文样例和误报处理 |
| 经核验的紧急资源清单 | 地区、服务名称、联系方式、服务对象、适用风险、可用时间、来源、最近核验时间、维护人及失效替代渠道。需求表给出的号码和名称属于待核验输入，不代表本系统已验证其服务范围或能力 |
| 人工客服与专家机制 | 是否已有工单系统、排班和接收队列；工作/非工作时段策略、分派方式、普通和高风险响应时限、回复权限及人工结束条件 |
| 未成年人通知策略 | 平台怎样给出可信年龄/适用规则信息，哪些角色可获通知、何时通知、通知范围、人工复核和例外流程，由指定负责人批准并版本化 |
| 保留与删除策略 | 普通与高风险会话分别的保留期限、风险锁定依据、解除权限、到期处理、用户删除结果、工单/审计/备份副本范围；“高风险不可删除”不能自动解释为永久保存 |
| 加密与访问规则 | 谁能看原文、谁只能看脱敏内容、工单摘要可携带哪些信息；存储和传输加密、密钥归属、审计与导出控制由谁维护 |
| 质量与服务目标 | 领域覆盖、证据引用、风险识别、误报、延迟、并发、模型成本、人工响应时限和运营统计周期的验收口径及阈值 |

风险通道不在没有接收人、服务核验和故障兜底的情况下宣称已形成闭环。紧急提示、风险事件落库、工单派发、人工受理和最终处置是不同状态，均需分别验收。

## 4. 小程序与平台同事需要提供的接口合同

| 合同 | 需给出的字段或规则 | AI 侧需要的结果 |
| --- | --- | --- |
| 平台服务身份 | 调用方标识、鉴权方式、签名/密钥或短期凭据、有效期、撤销、允许调用范围；测试环境样例 | 确定受信调用者，拒绝过期、伪造、越权请求；长期服务凭据不放入小程序 |
| 用户身份映射 | 受信 user/tenant/channel 标识、用户注销状态、平台权限与年龄/地区属性的可信来源；如为多租户需给租户隔离规则 | 从网关验证后的身份上下文确定用户，不能信任任意 body.user_id |
| 会话与流式代理 | 会话建立/续聊方式、请求幂等键、事件格式、超时、心跳、缓存/压缩/缓冲规则、断连处理、重连和停止生成合同 | 小程序实际网络路径下能逐事件接收、取消和恢复，避免只在浏览器演示可用 |
| 语音能力 | ASR/TTS 归属、接口/供应商、语言、音频编码/大小/时长、置信度定义、延迟、错误码、临时文件和授权范围 | 决定只接收文本还是处理音频；识别失败不创建错误咨询轮次，语音播放只使用安全回复 |
| 功能动作字典 | action_code、展示文案、参数 allowlist、功能权限/可用性、地区或用户条件、失效状态、对应版本 | AI 返回结构化动作，不硬编码小程序路由；前端将动作解析为真实页面 |
| 来源查看 | 来源 ID 的打开方式、官方原文允许域名、附件访问方式和权限、文档页码/段落定位支持 | 来源标注可以核对，过期/无权限来源有明确提示，不返回服务内部地址或令牌 |
| 转接/转介工单 | 创建、查询、状态/回复回调、事件签名、防重 ID、单号、原因、摘要、风险记录关联、目标队列、受理人/状态/时间、回复内容/时间 | 能区分 pending/accepted/failed 等状态，回调防伪、防重并校验状态先后顺序 |
| 消息通知 | 用户接收标识、消息模板、渠道、授权条件、发送回执、重试/去重、失败兜底 | 人工回复和提醒可追踪；消息包含必要最少信息，不默认把完整风险原文推送到外部通知 |
| 前端与业务统计 | 曝光/点击/跳转/到达/办理结果事件、event_id、时间、action_code、回答/会话关联、去重及回传权限 | 推荐卡片产生转化链路；服务端收到点击事件不等于业务已经办结 |
| 运营与客服界面 | 是否已有知识维护、FAQ、反馈处理、人工回复、风险处理界面；角色权限、查询范围与审计方式 | 明确是提供 API 对接还是另建后台，避免在 AI 接口开发中隐含承担整套运营前端 |
| 取消、删除和通知联动 | 用户停止生成、退出页面、删除普通会话、注销账号时平台要调用的动作及展示文案 | 取消与删除分开；常规生成取消不等同于撤销风险事件或工单 |

推荐优先沿用“平台后端校验现有登录态，再调用 AI 服务”的链路。流式响应由平台代理还是让前端持短期受限凭据直连，需要结合小程序网络 API、域名白名单及网关能力联调确认。

## 5. 需要先统一的业务口径

### 5.1 连续两次无法回答

建议以同一会话连续两轮服务端判定无法作答触发人工入口，成功回答后清零；澄清问题、业务完成前取消、高风险处理、正常合规拒答不计入知识无答案。初稿将检索无证据、超出范围、依赖故障导致无法作答纳入计数；最终口径和用户“未解决”反馈是否计入，由客户确认。

计数按服务端会话顺序原子更新，每轮最多提交一次。审核结果落库时与 generation 的 completed 终态一起提交，随后即使停止分段发送并将 delivery_status 记为 aborted，也不回滚计数；业务完成前成功取消才记 cancelled 且不计数。没有回答的 failed 结果及任务状态查询也须返回服务端计数和人工入口状态，不能因缺少 answer_id 漏掉第二次依赖失败后的转接提示。字段及竞态处理见 [接口合同](05-api-contract.md)。

系统故障不能被统计为模型已回答。是否创建转接单由入口动作和转接合同决定；“展示转人工入口”与“已成功转人工”是两个结果。用户显式要求人工不再强制走完整检索和生成后才给入口。

### 5.2 人工与高风险时限

普通转接的“24 小时未受理”需确认起算点、自然时长还是工作时长、首次提醒和重复提醒规则、已受理的准确含义。提醒应由持久化任务调度或带状态检查的 worker 实现，重启后可继续，重复执行不重复发送。

高风险需要立即返回紧急资源与人工通道，并将风险事件及派发意图持久化；外部工单通过 outbox 等可恢复机制派发，超时保留待重试状态。不能等待外部工单请求成功后才展示紧急提示，也不能让高风险进入普通 24 小时待受理队列。

### 5.3 会话和工单状态

建议至少区分：回复生成状态、已审核正文的传输状态、会话风险标记、风险处置状态、人工工单状态、通知发送状态。审核结果持久化后生成任务已经 completed，停止传输不能将其改成 cancelled，也不删除完整已审核答案。每条外部状态回调绑定平台单号、内部事件和幂等键，经过鉴权后推进状态，迟到或重复回调不能使已完成状态倒退。

普通删除应覆盖业务消息、checkpoint、摘要、缓存及关联后台写入；实际删除方式和备份范围按客户批准的策略执行。高风险受控留存需要明确授权、到期处理及用户可见的结果，不能只在前端隐藏删除按钮。

### 5.4 指标定义

| 指标 | 建议定义草案 | 需确认的边界 |
| --- | --- | --- |
| 回答率 | 完成并具有约定回答状态的轮次 / 纳入统计的有效提问轮次 | 区分 grounded_answer、clarification、refused、unable、risk_response 和 error；不能把“已返回任意文本”都算有效回答 |
| 满意率 | 明确正向评价数 / 有明确正负评价的回答数 | 同时报评价覆盖率；未评价不能默认满意；一人反复操作按约定去重或更新 |
| 转人工率 | 发生有效转接的会话数 / 纳入统计的会话数 | 单列请求、建单、派发、受理和回复；高风险自动转介单列，避免重复计数 |
| 来源覆盖率 | 有可核对证据引用的领域事实性回答 / 需要来源的事实性回答 | 来源真实存在、对应该事实且适用，不能只检查 citation 数量大于零 |
| 功能转化 | 卡片曝光 → 点击 → 目标页到达 → 办理动作 | 办理结果必须由目标业务模块回传，AI 服务不可自行推断 |
| 未命中/低分清单 | 关联输入主题、回答结果、证据/知识版本及经脱敏的反馈 | 导出权限、保留期限、纠错处理闭环及是否纳入下一知识版本 |

## 6. 资料未到时可以先做什么

| 可先推进 | 前提和边界 |
| --- | --- |
| 工作流、API/事件合同、数据模型和状态机 | 标明 proposed，保留待确认字段；尚未实现的接口不写成已可调用 |
| 可信用户适配与权限测试 | 用仅本地可用的模拟身份替身，不把调试后门带到生产 |
| RAGFlow 适配器和引用结构 | 用虚构、明确标记的测试知识，不把演示内容或失效政策当正式依据 |
| 输入/输出守卫、风险与人工路由 | 使用审校待办和模拟结果，验证路径覆盖；正式话术、阈值及资源配置仍需负责人确认 |
| 工单与通知 outbox | 先对接 mock 接收端，验证超时、重试、防重和重启恢复；界面显示模拟状态，不能声称真实人员已接单 |
| SSE、取消、历史、FAQ、反馈与统计 | 先与前端合同联调，虚构问题、来源和动作字典均需标记；上线前切换已批准配置 |

正式知识发布、政策现行结论、真实风险通知和生产受理闭环，需要完整材料及真实接收端；资料缺失时保留不可用/待配置状态，不生成伪造政策来源、人员或热线。

## 7. 分阶段验收

| 阶段 | 可审查的交付物 | 必须覆盖的通过场景 | 外部前提 |
| --- | --- | --- | --- |
| A：合同冻结 | 用户/服务鉴权、会话消息与 SSE、取消、引用、动作、工单、反馈 schema；责任与状态表 | 双方用相同示例验证字段/错误码；服务端不信任客户端身份与任意动作参数 | 平台后端/前端参与，客户确认业务边界 |
| B：问答闭环 | 审核知识 → RAGFlow → 有依据回复 → 来源展示 → 追问/无答案 → 人工入口 | 三类知识各有覆盖；失效/不适用证据不返回现行结论；无证据不编造；连续两轮 unable 和用户主动要求人工生效 | 少量完整审核材料、真实模型与检索环境 |
| C：风险与安全 | 入站/出站守卫、风险事件、可恢复工单派发、资源配置、人工通知 | 高风险抢占与多轮升级、检测依赖失败、工单超时不阻塞提示、重复事件不重复建单、风险状态不因取消被删除 | 审核规则/样例、核验资源和人工接收机制 |
| D：小程序集成 | 浮窗对话、流式与停止、语音降级、来源打开、功能卡片和消息通知 | 真机/平台代理路径下流式可用；前后台切换/重连不重发；低置信度语音修订；卡片权限与来源参数正确 | 小程序/业务动作/ASR/TTS 及消息通道 |
| E：运营与上线 | 用户历史、受控删除、FAQ/反馈处理、知识发布更新、指标报表、容量与故障记录 | 跨用户隔离、风险保留限制、到期任务/后台恢复、知识撤回与缓存失效、反馈审校闭环、统计可复算 | 客户批准的数据策略、运营人员及目标值 |

每阶段同时保存确定性测试、真实依赖集成记录及质量评估结果。模板原有质量评估不能替代用户隔离、取消幂等、风险留存、工单防重和状态推进测试；验收指标阈值由双方书面确认，不在资料缺失时自行承诺。

## 8. 可直接发送的索取清单

给客户：请先提供经专业审核的知识/政策/流程/FAQ 原文件与完整出处、政策有效期和地区、业务动作对应关系、参考问答与反例、风险分级/话术和经核验的紧急资源、客服排班/受理机制，以及普通与高风险会话的保留和通知规则。每个内容包请指定维护人、审校人和更新频率。

给小程序/平台同事：请提供服务调用鉴权与可信用户映射、流式代理和停止生成约定、动作字典与允许参数、来源打开方式、ASR/TTS 归属和接口、工单创建/状态/回复回调、消息通知、统计回传及已有运营后台说明，并准备测试环境和脱敏样例。
